# Understanding a Gemini API Response

Below is a simplified and formatted version of the response returned by the Gemini API.

```python
response = GenerateContentResponse(
    sdk_http_response=HttpResponse(
        headers={...}
    ),

    candidates=[
        Candidate(
            content=Content(
                parts=[
                    Part(
                        text="To understand Agentic AI, think of the difference..."
                    )
                ],
                role="model"
            ),

            thought_signature=b"...",
            finish_reason="STOP",
            index=0
        )
    ],

    model_version="gemini-3-flash-preview",

    prompt_feedback=None,

    response_id="4kS7aoKEFYDEg8UQ...",

    usage_metadata=GenerateContentResponseUsageMetadata(
        prompt_token_count=12,

        prompt_tokens_details=[
            ModalityTokenCount(
                modality="TEXT",
                token_count=12
            )
        ],

        thoughts_token_count=545,

        candidates_token_count=706,

        total_token_count=1263
    ),

    automatic_function_calling_history=[],

    parsed=None
)
```

---

## 1. `sdk_http_response`

```python
sdk_http_response=HttpResponse(
    headers={...}
)
```

Contains HTTP-level information about the API response, such as HTTP headers.

You normally don't need to interact with this when simply using the generated response.

---

## 2. `candidates`

```python
candidates=[
    Candidate(...)
]
```

A **candidate** is a response generated by the model.

The API can theoretically return multiple candidate responses:

```text
candidates
├── Candidate 0
├── Candidate 1
└── Candidate 2
```

In this response there is only one:

```python
index=0
```

So `candidates[0]` is the model's generated response.

---

## 3. `Candidate.content`

```python
content=Content(...)
```

Contains the actual content generated by the model.

Inside it:

```python
parts=[
    Part(...)
]
```

A response can contain multiple parts.

For example, parts can contain:

```text
Text
Function call
Other supported content
```

---

## 4. `Part.text`

```python
text="To understand Agentic AI, think of the difference..."
```

This is the **actual text generated by Gemini**.

In your response, this is the long explanation about Agentic AI.

So if you simply want the model's answer, you generally access the text rather than looking at the entire `Candidate` object.

Conceptually:

```text
API Response
     ↓
candidates[0]
     ↓
content
     ↓
parts[0]
     ↓
text
     ↓
Actual AI response
```

---

## 5. `role`

```python
role="model"
```

Indicates who produced the content.

Common roles include:

```text
user  → content from the user
model → content generated by the AI
```

Here:

```python
role="model"
```

means Gemini generated this content.

---

## 6. `thought_signature`

```python
thought_signature=b"..."
```

This is internal metadata associated with the model's reasoning process.

It is **not the readable version of Gemini's thoughts**.

You generally don't need to interpret this value manually.

Think of it as:

```text
thought_signature
        ↓
Internal reasoning-related metadata
```

---

## 7. `finish_reason`

```python
finish_reason="STOP"
```

Tells you why the model stopped generating.

`STOP` generally means:

```text
The model completed its response normally.
```

Other finish reasons can indicate things such as reaching a token limit or other termination conditions.

---

## 8. `index`

```python
index=0
```

Identifies the position of this candidate in the `candidates` list.

Since this is:

```python
candidates[0]
```

its index is:

```python
0
```

---

## 9. `model_version`

```python
model_version="gemini-3-flash-preview"
```

Identifies the Gemini model/version that generated the response.

This is useful for debugging and tracking which model produced a result.

---

## 10. `response_id`

```python
response_id="4kS7aoKEFYDEg8UQ..."
```

A unique identifier for this particular API response.

Useful for tracking/debugging requests.


# AFC Warning

You also received this message before the response:

```text
Direct use of automatic function calling (AFC) in
Models.generate_content is not recommended.

Instead, we recommend to use AFC in
Chat.send_message.

Similarly, direct use of AFC in
Models.generate_content_stream is not recommended.

Instead, we recommend to use AFC in
Chat.send_message_stream.
```

### What does this mean?

**AFC = Automatic Function Calling.**

It allows Gemini to automatically decide when to call functions/tools that you provide.

The SDK is telling you that if you're using AFC, it recommends using the **Chat API**:

```python
Chat.send_message()
```

instead of directly using:

```python
Models.generate_content()
```

For streaming:

```python
Chat.send_message_stream()
```

is recommended instead of:

```python
Models.generate_content_stream()
```

This is a **SDK recommendation/warning, not an error**. Your request still completed successfully because:

```python
finish_reason="STOP"
```

# The Most Important Parts to Remember

When working with this response, the main structure is:

```text
GenerateContentResponse
│
├── candidates
│   └── Candidate
│       ├── content
│       │   └── parts
│       │       └── text      ← Actual AI response
│       │
│       ├── finish_reason     ← Why generation stopped
│       └── index              ← Candidate number
│
├── model_version              ← Which model was used
│
├── response_id                ← ID of this response
│
├── usage_metadata
│   ├── prompt_token_count     ← Input tokens
│   ├── thoughts_token_count   ← Reasoning tokens
│   ├── candidates_token_count ← Output tokens
│   └── total_token_count      ← Total
│
└── automatic_function_calling_history
    └── []                     ← No automatic tool calls
```

### The simplest mental model

```text
              YOUR PROMPT
                   │
                   ↓
            12 input tokens
                   │
                   ↓
              ┌─────────┐
              │ Gemini  │
              │  Model  │
              └────┬────┘
                   │
             545 thought
                tokens
                   │
                   ↓
           706 output tokens
                   │
                   ↓
              candidates[0]
                   │
                   ↓
             content.parts
                   │
                   ↓
                text
                   │
                   ↓
          Actual AI response
```

**In short:**

> `candidates[0].content.parts[0].text` → **the answer you want to display**

> `usage_metadata` → **how many tokens were used**

> `thought_signature` → **internal reasoning-related metadata**

> `finish_reason` → **why generation stopped**

> `automatic_function_calling_history` → **what automatic tool/function calls occurred**

UNDERSTANDING CONFIG PARAM:

"Google documents these as part of Gemini's generation configuration."
generate_content(
    model = "which model?",
    contents = "what do I want?",
    config = {
        "how should it behave/generate?"
    }
)

Important things you can put in config
Config option	    What it does
system_instruction	Gives persistent behavioral instructions [like a prompt telling how to perform tasks]
temperature	        Controls generation randomness
max_output_tokens	Limits maximum output length (can include thought tokens)
top_p	            Controls token-selection diversity
top_k	            Controls token-selection pool
stop_sequences	    Tells generation when to stop
response_schema	    Defines the structure expected in structured output
tools	            Gives the model capabilities such as search/function calling/code execution
response_mime_type	Can request formats such as JSON [but you also give instructions in the content param of what format do you want of the data else gemini generates a random pattern of json or we use **response schema**]



**temperature**-

Possibilities
blue       80%
clear      10%
beautiful   5%
dark        3%
green       1%
...

At a low temperature, the model tends to strongly favor the high-probability choices.So,..
"The sky is blue."
"The sky is blue."
"The sky is blue."

At a higher temperature, lower-probability choices have a better chance of being selected.
"The sky is blue."
"The sky is clear."
"The sky is beautiful."
"The sky is dark."

->"random" doesn't mean the model suddenly generates nonsense. It means the probability distribution is made flatter, so alternative token choices become more likely.

-> error retry with "exponential backoff":

def send_with_retry(message, max_retries=3):
    for attempt in range(max_retries):
        try:
            return chat.send_message(message)

        except Exception as e:
            print(f"Request failed: {e}")

            if attempt == max_retries - 1:
                raise

            wait_time = 2 ** attempt

            print(f"Retrying in {wait_time} seconds...")
            time.sleep(wait_time)

The code above catches every exception. That's okay for learning the concept, but in a production application you shouldn't retry every error.

example-:
Rate limit / temporary server error
        → retry ✅

Invalid API key
        → don't retry ❌

Invalid request
        → don't retry ❌
